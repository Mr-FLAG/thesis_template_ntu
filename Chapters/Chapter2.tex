\section{Fairness}
% To be modified further.
In modern computing-intensive systems, fairness is a critical performance metric for preventing job starvation and meeting quality of service (QoS) requirements. Existing works have proposed a number of fairness mechanisms for resource allocation with various objectives. In this section, we summarize the prior work focusing on fairness as follows.%Fairness can be defined in various ways, depending on the specific context and objectives of the system. In this section, we review the existing literature on fairness in both single-cluster and distributed job execution scenarios.

\subsection{Fairness in Single-site System}
A multitude of notions exist for different types of fair resource allocation. The most widely used resource allocation policy in the single-site system is the Processor Sharing (PS) policy, which allocates resources (i.e., system processing capacities) evenly to pending jobs. When job workloads are unknown and only explicit resource demands are provided, the PS policy degenerates to Max-min Fairness (MMF). Radunovic \textit{et al.} \cite{radunovic2007unified} proved that the max-min fair allocation exists uniquely on any compact and convex set and presents general algorithms for computing the MMF resource allocation in the single-site system, which progressively maximizes the most unsatisfied job using a water-filling approach. 

In addition, there are other notions of fairness such as proportional fairness (allocating resources proportionally to the jobs' demands) and weighted max-min fairness. Mo \textit{et al.} \cite{mo2000fair} proposed $\alpha$-Fairness to provide a unified mathematical framework for these concepts. Suppose the resource allocation is a vector $\mathbf{x} = (x_1, x_2, \dots, x_n)$ where each component $x_i$ represents the resource allocation to the $i$-th user, $\alpha$-Fairness defines the utility function of each user as $U_\alpha (x_i) = \frac{x_i^{1-\alpha}}{1-\alpha}$ if $\alpha \ne 1$ and $U_\alpha (x_i) = \ln x_i$ if $\alpha = 1$. If $\alpha=0$, the $\alpha$-Fairness becomes efficiency-targeted, aiming to maximize the total system utility; when $\alpha=1$, it becomes the proportional fairness; when $\alpha \rightarrow \infty$, it becomes the max-min fairness. In addition, Ghodsi \textit{et al.} \cite{choosy} addressed task placement constraints (i.e., each task can only be assigned to a certain subset of machines in the system) and presented Constrained Max-min Fairness (CMMF), which tries to meet the fairness target by recursively satisfying the users based on the order of dissatisfaction. Note that these fairness notions focus on instantaneous resource allocation, which does not necessarily guarantee long-term fairness among jobs (and it depends heavily on how the system defines long-term fairness). Friedman \textit{et al.} \cite{friedman2003fairness, friedman2003protective} presented the notion of protective scheduling, which sets the criterion of long-term fairness to be that no job would finish later than its completion time under the PS policy. Under this fairness guarantee, they presented a series of algorithms to further improve the job processing efficiency. %Foe example, jobs of large resource demands and short processing times will be assigned with more resource than jobs of less demands but longer processing times in MMF. %In this dissertation, we focus on the fairness of instantaneous resource allocation among jobs in distributed job execution cases.

\subsection{Fairness in Multi-resource Allocation}
Some works have focused on the fair resource allocation problem with multiple resource types. Zahedi and Lee \cite{REF} solved the multi-resource allocation problem by proportionally allocating different resources based on the re-scaled Cobb-Douglas Utility and named it Resource Elasticity Fairness (REF). REF defines each user's utility as $u_i(x_i) = \alpha_{i0} \prod_{r=1}^Rx_{ir}^{a_{ir}}$, where $x_{ir}$ denotes the allocation of resource type $r$ to the $i$-th user and $\alpha_{ir}$ denotes the preference of the $i$-th user to resource type $r$ ($\alpha_{i0}$ represents the overall preference). Ghodsi \textit{et al.} \cite{DRF} proposed Dominant Resource Fairness (DRF) which decides users' resource allocations by their dominant shares, i.e., the resource the user demands the most in terms of proportion among all resource types. Gutman and Nisan \cite{gutman2012GDF} pointed out that DRF actually uses $L_{\infty}$-norm (i.e., the fair allocation focuses on the dominant resource only and neglects other resources) to measure the utility of each user and further presented Generalized Resource Fairness (GRF) which allows measuring the fairness of multi-resource allocation with a wider range of norms. Wang \textit{et al.} \cite{wang2014dominant} proposed DRFH, which generalizes DRF to heterogeneous servers in centralized cloud computing systems. In addition, Bonald and Roberts \cite{bonald2015multi} presented Bottleneck Max Fairness (BMF), which defines the fair share of each user as being assigned at least $1/n$ fraction of the bottleneck resource (i.e., the resource that is most demanded by all the users), and proved that BMF achieved better efficiency than DRF. Notably, these works focus on the fairness of multi-resource allocation in a single-site system, which is not directly applicable to our distributed job execution scenario considering network resources. 

Max-min Fairness and its extensions are widely used in many fields of networking. Fossati \textit{et al.} \cite{fossati2022distributed} presented a distributed slice multi-resource allocation algorithm specialized for centralized 5G systems, which allows using any single fairness notion to compute the allocation of each resource type. Li \textit{et al.} \cite{li2025fair} studied fair resource allocation based on various SLAs of users while improving the execution efficiency. Guo \textit{et al.} \cite{guo2024dynamic} presented a fair multi-resource allocation mechanism in cloud computing systems with elastic user demands. Further applications of MMF and its extensions can be found in cloud servers \cite{wang2014dominant}, heterogeneous GPU clusters \cite{mahajan2020themis}, 5G networks \cite{fossati2020multi} and LLM inferences \cite{sheng2024fairness}.

\subsection{Fairness in Distributed Job Execution}
Fairness is also widely studied in the case of distributed job execution, where the problem is further complicated by the capacity heterogeneity across different sites and the dynamic nature of job demand distributions. Chen \textit{et al.} \cite{chen2018scheduling} investigated achieving max-min fairness in terms of job response times in geo-distributed systems by task transmission, which imposed strict constraints that the number of tasks is no more than the number of computing slots in the system so that there is no resource contention. Guan \textit{et al.} \cite{AMF} introduced Aggregate Max-min Fairness (AMF), which required the aggregate instantaneous resource allocation (i.e., the sum of resource allocations across all sites) of each job to be max-min fair among all possible aggregate resource allocations. They also presented a task assignment algorithm aimed at achieving AMF in distributed job execution. Li \textit{et al.} \cite{li2022towards} further extended AMF to the indivisible resource case where AMF may not exist (because the solution space is not convex in such scenarios), in which they proposed Distributed Lexicographical Fairness (DLF) and used an iterative algorithm to compute DLF allocation in polynomial time. Meskar \textit{et al.} \cite{meskar2022fair} presented a fair multi-resource allocation policy specialized for heterogeneous servers in edge computing. Li \textit{et al.} \cite{li2024fair} studied a similar problem with access constraint on each user to the servers in cloud-edge systems. In addition, there have also been research investigating job trace properties to design specialized scheduling or resource allocation algorithms \cite{tian2019characterizing, luo2021characterizing}.

In summary, although a number of fairness notions and implementations have been presented for fair resource allocation, most of them are confined to single-machine or single-site scenarios. There are works that investigate fair allocation in distributed job execution, but they usually impose strong constraints on the system model to simplify the problem, such as \cite{chen2018scheduling}, which assumes that the system has no resource contention, and \cite{AMF}, which ignores the network resources across sites. The problem of achieving fair resource allocation in distributed job execution considering network resources remains largely open.

\section{Efficiency}
Efficient scheduling plays a paramount role in all types of job processing systems. Early works on job scheduling problem were primarily restricted to a single machine or a cluster of machines. In modern computing-intensive systems, deploying multiple computing datacenters across geo-distributed locations has become a common paradigm, in which jobs typically disperse their tasks unevenly across different sites. Optimizing job processing efficiency in such distributed settings is non-trivial. We organize the related work focusing on efficient job scheduling as follows.


\subsection{Shortest Remaining Processing Time}
In the single-machine scenario, the Shortest Remaining Processing Time (SRPT) policy, also called Shortest Remaining Time First (SRTF), is universally recognized as the optimal policy for minimizing the average job response time. SRPT always serves the job with the least remaining workload (processing time) until all jobs finish \cite{wiki:SRT, echrage1968proof}. In addition, although SRPT is targeted at efficiency and neglects fairness, Bansal \textit{et al.} \cite{bansal2001analysis} proved that the degree of unfairness that SRPT may cause is small compared with fair policies such as Processor Sharing. SRPT has been widely adopted beyond job scheduling across various domains, such as enhancing flow control \cite{gao2018d, wang2022approximate} in the datacenter network. %Note that SRPT is not optimal if the system has multiple servers or clusters to process jobs \cite{}

Based on the SRPT policy, there have been a number of extensions targeted at various problem scenarios. A classic direction explores the performance of SRPT under stochastic job processing times and arrival patterns. Nuyens \textit{et al.} \cite{nuyens2006large} studied the performance of SRPT under light-tailed job processing time distributions and proved that SRPT achieves good tail-performance guarantees for most of the jobs in the system, compared with the First-In-First-Out policy. Lin \textit{et al.} \cite{lin2011heavy} investigated the heavy workload scenario and proved that the performance advantage of SRPT will become more significant under heavier-tailed distributions of job processing times. Banerjee \textit{et al.} \cite{banerjee2022heavy} and Ji \textit{et al.} \cite{ji2025heavy} characterized the remaining processing time distribution of jobs under the SRPT policy in heavy-traffic regimes with heavy-tailed and light-tailed job processing time distributions, respectively.

Another direction has studied how to modify SRPT in various cases to achieve higher processing efficiency. A natural extension of SRPT is to adapt it to multi-server systems where each job has to be assigned to one of the $k$ servers for execution, namely SRPT-$k$. SRPT-$k$ preemptively assigns the $k$ jobs with the smallest remaining processing time to the $k$ servers. Mailach \textit{et al.} \cite{mailach2017scheduling} proposed Modified Comparison Splitting Scheduling (MCSS) as an extension of SRPT and SRPT-$k$ under inaccurate estimation of job processing times in both single-server and multi-server systems, outperforming the original SRPT when the number of servers is small. Grosof \textit{et al.} \cite{grosof2019srpt} studied SRPT-$k$ and proved that although SRPT-$k$ is non-optimal, it converges to SRPT when the system utilization approaches $1$. In addition, Grosof \textit{et al.} \cite{grosof2022optimal} focused on multi-server job processing systems under heavy traffic and proposed two preemptive policies, ServerFilling-SRPT and ServerFilling-Gittins. These policies prioritize short jobs while avoiding unnecessary server idleness in scenarios with known and unknown job processing times, respectively. Specifically, ServerFilling-SRPT sorts pending jobs in ascending order of their remaining processing times. It then selects jobs from the head of the queue until their cumulative server requirement reaches or exceeds the total system capacity, and assigns these selected jobs in descending order of their required server counts.

\section{Efficiency in Distributed Job Execution}
The task (job) scheduling problem in geo-distributed environments has been widely studied from a variety of system scenarios and performance objectives \cite{gautam2015survey, ghomi2017load, hedayati2023mapreduce, wu2025task}. Since the job load and the system capacity are distributed (mostly unevenly) across multiple sites, the problem becomes significantly more complex because of the additional dimension of site-specific resource constraints and contentions along with inter-site communication overheads. Although the SRPT policy can be extended to such distributed job execution cases with some algorithmic variations, they all no longer guarantee optimality. Most existing studies solved the scheduling problem in distributed job execution by developing heuristic methods or formulating linear programs. For example, Hung \textit{et al.} \cite{hung2015scheduling} presented Workload-Aware Greedy Scheduling (SWAG), a workload-aware strategy which achieves superior performance compared to SRPT extensions. Specifically, SWAG iteratively computes the estimated completion time of each unscheduled job by assuming that this job is executed next, while taking the scheduled workloads into consideration. Then, it adds the job with the earliest completion time to the execution order, adds the job's workload to the scheduled workload and starts the next round of calculation, repeats the process until all jobs are scheduled. SWAG is a heuristic method and neglects to utilize task transmissions to further improve the efficiency. Guan \textit{et al.} \cite{guan2022task} and Zhao \textit{et al.} \cite{zhao2025data} studied the scheduling problem given that the input data of each task is replicated across multiple sites and the task can be assigned to any of them, without accounting for inter-site network resources. Hu \textit{et al.} \cite{hu2016flutter} and Pu \textit{et al.} \cite{pu2015low} focused on the efficient task assignment problem in distributed job execution incorporating task transmissions, but they assumed only one job in the system and did not study the scheduling strategy across jobs. Hung \textit{et al.} \cite{hung2018wide} proposed Tetrium, a complete framework that incorporates both compute and network resources to improve the efficiency of map-reduce job execution, which focuses on the task assignment of each individual job and simply applies SRPT to schedule multiple jobs. Convolbo \textit{et al.} \cite{GEODIS} and Li \textit{et al.} \cite{li2020load} coordinated scheduling with task transmission in distributed job execution, which aimed at minimizing the makespan (i.e., the time span from the arrival of the first job to the completion of the last job in the system) instead of the average response time of jobs. Li \textit{et al.} \cite{li2021mapreduce} improved the MapReduce task scheduling efficiency by monitoring the idle containers in the geo-distributed system, modeling the task assignment problem as a bipartite matching problem and solving it via the classical Hungarian algorithm. Some research focused on utilizing game theory to minimize the individual user costs by assuming that users in the system have different interests, and thus they form a game model \cite{chen2014decentralized, hogade2022energy}. Recent studies have also adopted deep reinforcement learning to search for effective resource allocation strategies in fields like wireless networks \cite{wang2021incorporating}, edge computing \cite{li2022drl, mohajer2024dynamic}, satellite networks \cite{liao2020distributed, li2022multi} as well as conventional distributed data centers \cite{wei2022multi}. %However, learning-based approaches have mainly focused on improving the efficiency of resource allocation (such as system utility, revenue and profit) or achieving load balancing instead of achieving the fairness of resource allocation.

Many efforts have aimed to minimize bandwidth usage or the transmission time/cost in the system. For example, Hsieh \textit{et al.} \cite{hsieh2017gaia} presented Gaia to minimize the transmission cost between machine learning clusters while maintaining the model's performance, Chen \textit{et al.} \cite{chen2021optimizing} focused on optimizing the transmission time of data along given paths, and Shi \textit{et al.} \cite{shi2024adaptive} aimed to save the network bandwidth usage on both intra-datacenter and inter-datacenter links while ensuring the QoS of microservices. In addition, Zhao \textit{et al.} \cite{zhao2019optimizing} modeled the scheduling problem in geo-distributed systems as an extension to Hypergraph Partition-based Scheduling, which aims to save the WAN data transfer volume and improve system makespan, namely HPS+. 

In summary, given the diverse problem settings and various efficiency objectives in distributed systems, substantial research has explored this field from different perspectives. Distinct from the existing work, we focus on a more general system model of distributed job execution, in which we aim to minimize the average job response time by jointly considering the problems of job scheduling and task transmission.

Hung \textit{et al.} \cite{hung2015scheduling} presented a scheduling algorithm for distributed job execution, which selects the job with the least overall demand to run first in order to minimize the average response time of jobs. This allocation policy is straightforward but apparently unfair, and could cause starvation for large-demand jobs. Different from the above work, we aim to achieve max-min fairness in the instantaneous resource allocation among jobs across geo-distributed sites given the availability of network resources.
